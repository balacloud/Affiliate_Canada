Selected persona

Product Evidence / Editorial

Checks exact-product claims against traceable sources and preserves unresolved evidence.

Typical input

Exact variant, source record, dated baseline, method and current hold reasons.

Accountable output

A sourced finding or uncertainty, a change record and a proposed editorial disposition.

Checks that matter
  • Exact variant and claim scope.
  • Source supports wording; missing evidence remains missing.
  • Ingredient disclosure is separate from a safety verdict.

03 / Recurring product-evidence work

A daily evidence monitor, with review.

Yes, we can give this work a focused persona and agent. A prompt alone cannot guarantee correct daily decisions. The operating design makes sources, coverage, changes and unresolved gaps reviewable.

Research regularly. Preserve the hold.

Monitor the existing four candidates. Report a newly supported fact, a meaningful change, a conflict or an access failure. Propose editorial review when warranted. Storefront updates and publication remain separate.

Exact variantsDated source evidenceVisible uncertaintyReport-only writes
1Load the baseline

Current working files, exact IDs and latest completed report. Preserve the input snapshot.

2Reopen primary sources

Verify the selected fields on exact-product pages. A snippet or HTTP 200 is not enough.

3Compare each field

Separate changed, unchanged-in-checked-fields, conflicting, inaccessible and unattempted.

4Write a dated report

Changes, source URLs, actual access dates, coverage and unresolved holds. Never overwrite history.

5Review before release

Founder/editorial owner assesses the proposed change. Implementation and publishing checks follow.

The monitor can do

  • Recheck origin wording, ingredient disclosure, price, stock and relevant policies.
  • Preserve exact evidence and detect meaningful field changes.
  • Flag conflicting formulas and newly available information.
  • Say what was not checked or could not be accessed.
  • Prepare questions and a focused outside-research prompt for unresolved gaps.

It cannot establish by browsing alone

  • Physical-label or batch evidence it has not received.
  • Independent manufacturing proof from a brand-wide claim.
  • Universal safety, medical suitability or regulatory clearance.
  • A complete screening result from missing ingredients or unknown conditions.
  • Recommendation status, public changes or publication without a separate reviewed task.

Ready-to-use recurring task prompt

Select this project when creating the task. A new worktree may omit current uncommitted content and configuration; checkpoint deliberately before using that mode.

Run the SmartShopCA Product Evidence Monitor using docs/stable/PRODUCT_EVIDENCE_MONITOR.md and $smartshopca-product-research. Read current working-tree content and the most recent completed report. Recheck the four exact face/body candidates against public primary sources. Save a new dated report only under docs/Research/product-monitor/. Return material changes, source-access failures, checked coverage and unresolved holds. Do not edit app/content/status files, clear holds, send messages, spend money, commit, push or deploy. If web access is unavailable, report blocked rather than claiming verification. Use product_evidence_monitor if available; otherwise perform the same bounded workflow in the main task.
How we judge whether the monitor is dependable

Expected cases include brand-wide versus exact-SKU origin, wrong variant, inaccessible pages, ingredient conflicts, missing concentration and physical-label gaps. A fabricated visit, unsupported safety/origin claim, cleared hold or unauthorized external action fails the pilot.

The full runbook defines twelve acceptance cases. They are planned behavioral evaluations, not completed tests or an accuracy percentage.

04 / The email layer

Kit brings interested readers back.

Kit, formerly ConvertKit, is an email-marketing platform. For SmartShopCA, the intended use is a subscriber list, separate topic preferences and occasional updates when useful comparisons or seasonal collections are ready.

Not connected to the websiteNo signup available today
Reader chooses a topic→Website sends a real request→Kit + confirmation→Relevant email updates

Planned Kit responsibilities

  • Manage opted-in subscribers and subscription status.
  • Separate seasonal and care interests; support a both-topics choice.
  • Send newsletters and planned welcome/confirmation flows.
  • Handle unsubscribe requests and email engagement reporting.

Specific automation features depend on the account's plan and configuration; these were not checked in the account.

Separate systems, separate jobs

Business inbox: receives corrections and contact messages.

Kit: sends email updates to interested subscribers.

Evidence Monitor: produces product-research reports for review.

Kit does not research products, verify ingredients or decide what passes our editorial checks.

The website currently shows an honest unavailable notice. It needs a real server-side Kit action, topic/consent handling, confirmation, provider-error handling and a matching privacy update before collection begins. Kit's official product overview.
