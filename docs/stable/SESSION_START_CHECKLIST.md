# Session Start Checklist

> Use this at the beginning of any implementation session, whether the active coding agent is Claude Code, Codex, or a future replacement.

## Read Order

1. `AGENTS.md`
2. `CLAUDE_CONTEXT.md`
3. `docs/stable/GOLDEN_RULES.md`
4. `docs/stable/ROADMAP.md`
5. latest `docs/status/PROJECT_STATUS_*.md` relevant to the current phase
6. latest `docs/versioned/KNOWN_ISSUES_*.md` relevant to the current phase
7. `docs/stable/BRAND_ARCHITECTURE.md` for positioning, navigation, taxonomy, or pillar work
8. `docs/stable/TECH_SPEC.md` if touching architecture, data models, routes, or components
9. `docs/Research/Codex_Transition_Handoff.md` when transition history matters
10. `PLAN.md` only for the original plan; it contains historical single-pillar assumptions

## Before Making Changes

- confirm current version and current phase
- identify blockers that require user input
- distinguish documented intent from implemented behavior
- verify whether code and docs still match

## Output Expected From The Session Lead

After the read pass, state:

- current version
- current top priority
- blockers
- recommended next task

## Closing Rule

If the session materially changes product behavior, architecture, or priorities, update the relevant docs before ending the session.
